あなたはこのリポジトリ（自分専用の知識ベース）の取り込み工程を、無人で担当しています。
これから Obsidian から取り込んだ 1 つの md を読み、**ページの器に必要な情報を決める**だけを行います。
ファイルの作成・編集は一切しません（読むだけ）。

## 対象

`docs/{{MD_FILE}}`

## 先に読むもの

1. `docs/{{MD_FILE}}` — 今回の原文
2. `content/labels.json` — ラベルレジストリ。各ラベルの `description` が判断材料
3. `docs/label-spec.md` — ラベルの仕様

## 決めること

- **mainLabel** — 「フォルダを作るならどこに置くか」がちょうど 1 つ。`<アプリ>/<セクション>` の**2段ちょうど**。
  `content/labels.json` に実在し、`section: false` が付いていないものだけが使えます。
  判断の基準は**公式ドキュメントのどのセクションに載っている話か**であって、自分の感覚ではありません。
- **subLabels** — 0 件以上。**既存レジストリにあるラベルだけ**を選びます。
  新しいラベルは作りません（無人実行では新設を禁止しています）。Q&A 形式の記事なら `Blender/Q&A` が該当します。
  mainLabel と同じものは入れません。
- **title** — 一覧で見て中身が分かる短い日本語。ファイル名の `Q&A_` 接頭辞や拡張子は含めません。
  原文の frontmatter に `title` があればそれを尊重しつつ、冗長なら整えます。
- **summary** — 1〜2 文。**結論から**書きます（「原因は3つ。最も多いのは…」のように）。
  一覧でこれだけを見て、開くかどうかを判断できることがすべてです。

## skip する条件

次のいずれかに当たるなら、`decision: "skip"` にして `reason` に何が決められなかったかを書いてください。
**無理に当てにいかないこと。** 見送ったものは本人が翌朝ログで確認し、md に手を入れれば自動で再挑戦されます。

- mainLabel の候補が複数あって、公式ドキュメントの構成から見てどれとも決めきれない
- 原文が短すぎる・書きかけで、ページにしても読めるものにならない
- 内容がレジストリのどのアプリ（第一階層）にも属さない

## 出力

指定された JSON スキーマに従って返します。`decision: "create"` なら `title` / `mainLabel` / `summary` は必須です。
`reason` は日本語で 1〜2 文。ログに残り、本人が朝に読みます。
