ページの器はすでに作られています。あなたの仕事は **本文 HTML を 1 枚書くこと**だけです。

## 書き込んでよいファイル

`content/pages/{{SLUG}}/index.html` — **これ 1 つだけ**。

`meta.json`・`content/labels.json`・`docs/` 配下は**触らないでください**（別の工程が責任を持っています）。
`npm` やその他のコマンドは実行しません。

## 材料

1. `docs/{{MD_FILE}}` — 原文。ここに書かれていない事実を足さないこと
2. `content/pages/{{SLUG}}/index.html` — 雛形。ここに定義済みのテーマトークンと体裁を土台にする
3. `docs/design.md` の「## 7. ページ HTML の規約」— 守るべき規約
4. `content/pages/{{REFERENCE_SLUG}}/index.html` — 既存ページ。**文章の密度と見出しの粒度をこれに合わせる**

## タイトル

`<title>` と `<h1>` は次の文字列を使ってください（meta.json と揃えるため）:

{{TITLE}}

## 守ること（保存前に自分で確認）

- 外部ホストへの参照がゼロ（CDN・Web フォント・外部画像・fetch/XHR。CSP で機械的に遮断されるので、書いても表示されません）
- `<!doctype html>` から `</html>` まで完結した文書
- 明色・暗色の両方で読める（色は雛形の `:root` と `@media (prefers-color-scheme: dark)` のトークンを使う。新しい色を足すなら**必ず両方**に定義する）
- 横幅 375px で文書本体が横スクロールしない（広い表やコードは `pre` / `.scroll-x` の内側でスクロールさせる）
- 雛形の「ここから本文を書く。」というプレースホルダの文が残っていない

## 書き方

原文は Q&A 形式のメモです。読み返すのは**同じ場面でまた詰まった数ヶ月後の自分**なので、次を優先します。

- **結論を先に。** 「何が原因で、どうすれば直るか」を最初の段落に置く
- 操作手順は番号付きリスト。UI のラベルやショートカットは `<code>` で囲む
- 原因が複数あるなら表や見出しで分け、**切り分けの順番**が分かるようにする
- 図があると理解が早い箇所だけ、インライン SVG で描く（無理に足さない）
- 原文がスクリーンショットを参照していても、画像は取り込めません。**文章で説明に置き換えます**
- 原文にない推測・一般論で分量を増やさない

書き終えたら、何を書いたかを 1 行で報告してください。
