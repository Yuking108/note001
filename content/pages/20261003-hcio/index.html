ターミナルからレンダリングする（シーン・設定・出力先を指定）

Blender の画面を開かずに、保存済みの .blend の設定のまま、指定したシーンを指定したフォルダへ書き出す。画面描画に GPU を使わない分だけ速く、レンダリング中に他の作業もしやすい。本番のレンダリングはこちらを基本にしてよい。

ターミナルを開いたら パスを登録（手順1）→ 設定を確認（手順2）→ レンダリング（手順3）。この3つを毎回この順でやる。

実行されるのは保存済みファイルの設定。Blender で直した内容は ⌘ + S しないと一切反映されない。ファイル名やシーン名が変わったときは ★ の部分だけ書き換えれば使い回せる。

Premise前提

  • Blender 側で出力先・ルック・フレーム範囲を決めて ⌘ + S で保存してある
  • ターミナルを開く：⌘ + スペース →「ターミナル」と入力して Enter
  • 以降のコマンドはコピーして、ターミナルに ⌘ + V で貼り付け、Enter

Step 1ファイルの場所を登録する

ターミナルを開くたびに毎回実行する。

★ 2行目の FILE= を自分の .blend ファイルのパスに書き換える。

BLENDER="/Applications/Blender.app/Contents/MacOS/Blender"
FILE="/Users/theory/blender/2026_10/w4_speaker/blender/speaker.blend"
  • 実行しても何も表示されないのが正常
  • ターミナルを閉じると登録は消える。 開き直したら、もう一度これを実行する

Step 2シーンと設定を確認する

表示するだけで、レンダリングはしない。書き換え不要。

"$BLENDER" -b "$FILE" --python-expr "
import bpy
for s in bpy.data.scenes:
    r = s.render
    v = s.view_settings
    print('>> ===== ' + s.name + ' =====')
    print('>> エンジン       :', r.engine)
    print('>> カメラ         :', s.camera.name if s.camera else 'なし')
    print('>> 解像度         :', r.resolution_x, 'x', r.resolution_y, '(', r.resolution_percentage, '% )')
    print('>> フレーム       :', s.frame_start, '〜', s.frame_end, '/ fps', r.fps)
    print('>> 出力形式       :', r.image_settings.file_format)
    print('>> 出力先         :', bpy.path.abspath(r.filepath))
    print('>> ルック         :', v.view_transform, '/', v.look)
    print('>> 出力の色管理   :', r.image_settings.color_management)
    if r.engine == 'CYCLES':
        print('>> サンプル数     :', s.cycles.samples)
" 2>/dev/null | grep '^>>'

チェックするところ

項目 見るポイント
出力先 シーンごとに別フォルダになっているか。同じだと上書きされる。/tmp/ のままなら Blender の初期設定
フレーム 開始と終了が意図どおりか
ルック 変更した内容になっているか。ルックはシーンごとの設定
出力の色管理 FOLLOW_SCENE（シーンに従う）になっているか。OVERRIDE だとルックとは別の設定で書き出される

設定を直すときは、Blender で変更して ⌘ + S で保存し、もう一度ここを実行して確認する。

Step 3レンダリングする

A. 指定したシーンだけ（GPU を使う）

★ シーン名の部分を書き換える。数は増やしても減らしてもよい。

for SCENE in "Scene_001" "Scene_002" "Scene_003"; do
  echo "=== Rendering: $SCENE ==="
  "$BLENDER" -b "$FILE" -S "$SCENE" -a -- --cycles-device METAL
done

B. 全シーン（GPU を使う）

書き換え不要。ファイル内の全シーンを順番にレンダリングする。

"$BLENDER" -b "$FILE" --python-expr "import bpy; [print('SCENE:'+s.name) for s in bpy.data.scenes]" 2>/dev/null \
| grep '^SCENE:' | sed 's/^SCENE://' \
| while IFS= read -r SCENE; do
    echo "=== Rendering: $SCENE ==="
    "$BLENDER" -b "$FILE" -S "$SCENE" -a -- --cycles-device METAL < /dev/null
  done

< /dev/null は外さないこと。 これがないと最初のシーンだけで止まる。

While runningレンダリング中と完了後

  • Saved: '...0001.png' と出るたびに1枚保存されている
  • 最後に入力待ちの行（theory ~ ❯）に戻ったらすべて完了
  • ターミナルは閉じない。Mac はスリープさせない。 MacBook なら電源につないでおく
  • 途中でやめたいときは control + C（止め方は次の節）
  • 同じフォルダに前回の画像があると上書きされる。 残したい画像は先に移動しておく
  • レンダリング中に別の作業をしたいときは ⌘ + N で新しいターミナルを開く。新しいターミナルでは手順1をもう一度実行する

Stop途中で止める

止め方は3つ。上から順に試す。

方法1: control + C を何回か押す

control + C を、1回押すごとに2〜3秒待ちながら、ターミナルが theory ~ ❯ の行に戻るまで押す。

1回では止まらないことが多い。 今レンダリング中のシーンだけが止まり、次のシーンが始まってしまう。

方法2: ターミナルのウィンドウを閉じる（いちばん確実）

  1. ターミナルをクリックして ⌘ + W
  2. 「終了しますか？」と聞かれたら 「終了」

ウィンドウを閉じれば、中で動いているレンダリングも一緒に止まる。確実に止めたいときはこれ。

方法3: 新しいターミナルから止める

⌘ + N で新しいターミナルを開いて、次を貼り付ける。

pkill -f "Blender -b"

これはターミナルから動かしている Blender だけを止める。画面で開いている Blender は閉じない。

ただし、元のウィンドウはまだ次のシーンを始めることがあるので、そのあと元のウィンドウを方法2で閉じる。

止まったか確認する

新しいターミナルで次を実行する。

pgrep -fl "Blender -b"
結果 意味
何も表示されない すべて止まっている
何か表示される まだ動いている → 上の pkill をもう一度実行

なぜ control + C 1回で止まらないのか

control + C を押すと、Blender は今のレンダリングだけを止めて「普通に終了した」ように振る舞う。 そのためターミナル側は「正常に終わった、次のシーンへ進もう」と判断してしまう。

ループで複数シーンを順番に回しているときによく起きる動き。シーンを1つだけレンダリングしているときは、1回で止まることが多い。

止めたあとの確認

中断すると、最後のフレームが書き出されていない、または途中で終わっている可能性がある。再開する前に、出力フォルダの最後の画像を開いて確認し、おかしければ削除してからレンダリングし直す。

途中から再開したいときは -s（開始フレーム）で続きの番号を指定する。

Optionsよく使うオプション

書き方 意味
-b 画面を開かずに実行する（必ず最初に書く）
-S 名前 シーンを指定する
-a アニメーション全体をレンダリングする
-f 10 -a の代わりに使うと、10フレーム目だけ静止画で出力
-s 1 -e 24 1〜24フレームだけレンダリング
-o パス/#### 出力先を一時的に変える
-F PNG 出力形式を一時的に変える
-- --cycles-device METAL Cycles を Mac の GPU で動かす（コマンドの一番最後）

オプションの順番：-S -o -s -e -F は、必ず -a や -f より前に書く。

例: 出力先とフレーム範囲を一時的に変える

"$BLENDER" -b "$FILE" -S "Scene_001" -o "/Users/theory/Desktop/test/frame_####" -F PNG -s 1 -e 24 -a -- --cycles-device METAL

例: 1フレームだけ試し出し

"$BLENDER" -b "$FILE" -S "Scene_001" -f 1 -- --cycles-device METAL

Pitfallsつまずきやすい点

  • 保存していない変更は一切反映されない。 一番やりがちなミス。実行前に必ず ⌘ + S
  • 途中経過が見えないので、設定ミスに気づくのが最後になる。手順2の確認を挟むのはこのため
  • control + C は全体が止まる。1フレームだけ中断はできない
  • ターミナルを閉じるとパスの登録が消える。 新しいウィンドウでは手順1から

Why fasterなぜ速いのか

よくある誤解だが、バックグラウンド（-b）でも画像そのものはきちんとレンダリングされている。 省かれているのは「レンダリング」ではなく Blender の画面（GUI）の描画。

省かれるのは具体的に次のもの。

省かれるもの 効果
ビューポートや UI の描画 その分の GPU / CPU がレンダリングに回る
ビューポートが抱えているシーンデータ（VRAM） 空いた VRAM をレンダリングに使える。ここが一番大きい
レンダリング途中経過の画面表示 毎フレームの表示更新コストがなくなる

効果の大きさ

  • 通常は 数%〜十数%程度。劇的に速くなるわけではない
  • ただし VRAM が足りていなかった場合は効果が大きい。 GPU メモリに収まらず CPU に落ちていた／エラーで止まっていたシーンが、GUI を閉じた分の余裕で GPU のまま通ることがある
  • 重いシーン・長いアニメーションほど、積み重なって差が出る

Use GUI画面から実行したほうがよい場面

ターミナルが常に優れているわけではない。次の場合は Blender の画面から実行するほうが速く済む。

  • 1フレームだけ試し出しして、すぐ見たいとき（レンダー結果ウィンドウでそのまま確認できる）
  • 構図やライティングを詰めている最中（保存 → ターミナル実行の往復が無駄になる）
  • 途中経過を見ながらサンプル数を判断したいとき
