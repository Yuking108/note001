物理演算がレンダリングに出ない（レンダービューでは見えている）

レンダービューには出ているのに F12 の最終レンダーで消える。この症状の原因は2系統しかないので、順番に潰せば必ず見つかる。

結論：まず「レンダー専用の可視性トグル（カメラアイコン）」。次に「キャッシュ／ベイク」。

系統Aのトグルは1クリックで直るので先に見る。直らなければ系統B（シミュレーションの計算結果が無い／範囲外）を疑う。

系統 内容 なぜレンダービューでは見えるのか
A. レンダー専用の可視性トグル カメラアイコンがオフ レンダービューはこのトグルを無視する仕様（マニュアル明記）
B. シミュレーションのキャッシュ／ベイク 計算結果が無い／範囲外 ビューポートで再生したときのキャッシュが残っているから見える

Checkチェック順（この順番で見れば必ず見つかる）

  1. アウトライナー > フィルター（漏斗）> 制限の切り替え > カメラアイコンをオン

    オブジェクト／コレクションのカメラアイコンが閉じていないか？ → 原因1・3

  2. モディファイアのヘッダーのカメラアイコンがオフでないか？

    → 原因2

  3. レンダリングの開始フレームは、シミュレーション開始フレームと同じか？

    違うなら 物理プロパティ > キャッシュ > ベイク を実行。→ 原因4

  4. 剛体なら シーンプロパティ > リジッドボディワールド > キャッシュ。

    終了フレームがアニメーション長より短くないか？（既定 250）→ 原因5

  5. 流体なら ノイズ／メッシュ／飛沫を個別にベイクしたか？

    → 原因6

  6. パーティクルなら レンダー方法が「なし」になっていないか？

    → 原因7

  7. シーンプロパティ > 簡略化 の「レンダー」列が効いていないか？

    → 原因8

Principleなぜ「レンダービューでは見える」のか

レンダービュー（ビューポートのレンダープレビュー）はビューポート側の設定で評価される。 F12 の最終レンダーだけがレンダー側の設定で評価される。

Causes原因ごとの詳細

原因1オブジェクトの「レンダーで表示」がオフ ← 最有力

Show in Renders: “The object is able to be in the final render, note that it will still be visible in rendered shading view.”

（最終レンダーに含めるかどうか。レンダーシェーディングビューには残り続けることに注意）

つまり仕様として「レンダービューには映るが F12 では消える」状態が作れる。症状にそのまま一致する。確認・修正はどちらからでも同じ設定に届く。

  • オブジェクトプロパティ（オレンジの四角アイコン）> 可視性 > 表示 > レンダー のチェック
  • アウトライナー右上のフィルター（漏斗アイコン）> 制限の切り替え でカメラアイコンをオンにすると各行にカメラアイコンが出る → 閉じている（オフ）ものを開く
アイコン 効果（混同しやすい）
目 一時的に隠す（ビューポートのみ・保存されない）
モニター ビューポートで無効（レンダービューも消える）
カメラ 最終レンダーで無効（レンダービューには残る） ← 今回の犯人

原因2モディファイアの「レンダー」トグルがオフ

物理演算は多くがモディファイアとしてスタックに並ぶ（クロス、ソフトボディ、流体、ダイナミックペイント、パーティクルインスタンス、海洋など）。そのヘッダーのアイコン列は、オブジェクトレベルと同じ構造の罠になっている。

アイコン 意味
四角（頂点） 編集モードで表示
モニター ビューポートで表示（レンダービューもこれに従う）
カメラ レンダーで表示。オフだとレンダービューには出るが F12 で消える

原因3コレクションが「レンダーで無効」になっている

アウトライナーでコレクション行のカメラアイコンがオフになっていると、その中の全オブジェクトが最終レンダーから外れる。原因1と同じく、フィルター >「制限の切り替え」でカメラアイコンを表示して確認する。

原因4シミュレーションをベイクしていない

シミュレーションは Start と End の間の正のフレームでのみ計算される。

ベイクを推奨：再シミュレーションを避け、グリッチを防ぎ、シミュレーションの結果が毎回まったく同じになることを保証できる。

症状が出る典型パターン なぜ出ないか
途中フレームからアニメーションをレンダリングした（例：100〜200） 1〜99 が計算されていないので、物体が初期位置のまま
ファイルを開き直した／別マシンでレンダリングした キャッシュがメモリ上にしか無かった
ターミナル（バックグラウンド）からレンダリングした GUI の再生でキャッシュが作られないので、ベイクが事実上必須

対策は 物理プロパティ > キャッシュ（Cache）> ベイク（Bake） を押してからレンダリングすること。ベイクすると設定がロックされ、「ベイクを解放（Free Bake）」 を押すまで変更できなくなる＝結果が固定される。

原因5リジッドボディは「ワールド」側の範囲設定を見る

剛体はオブジェクト個別ではなく シーンプロパティ > リジッドボディワールド が計算範囲を持つ。

キャッシュサブパネルは「シミュレーションがアクティブなフレーム範囲を指定する」／「シミュレーションのベイクに使用できる」

開始 / 終了：「シミュレーションの最初と最後のフレーム」

ベイク：「シミュレーションを計算してキャッシュを保護する。ベイクするにはオブジェクトモードである必要がある」

  • 既定の範囲は 1〜250。251 フレーム以降をレンダリングするとそこで物理が止まる
  • アニメーションが 250 フレームを超えるなら終了フレームを必ず伸ばす
  • ベイクはオブジェクトモードでないと押せない（編集モードのまま探しても見つからない）

原因6流体（Mantaflow）は段階ごとに別ベイクが必要

ドメインの要素は個別にベイクする必要がある。

項目 ベイクが必要
ベース（液体／気体） 必須
ノイズ（気体の高解像度） 別途ベイク
メッシュ（液体の表面） 別途ベイク ← これを忘れると液体がレンダーに出ない
飛沫（パーティクル） 別途ベイク

キャッシュタイプが「リプレイ」だと再生時に都度計算するだけなので、最終レンダーでは信頼できない。「モジュラー」または「すべて」でベイクする。

原因7パーティクル／ヘアのレンダー設定

パーティクルが原因の場合は専用ノートに詳細がある。特に「エミッターをカメラアイコンで隠した」ケースが最も多い。

場所 設定 症状
パーティクルプロパティ > レンダー レンダー方法 = なし（None） ビューポートには点が出るがレンダーに何も出ない
同 > レンダー エミッターを表示 がオフ 発生元のオブジェクト自体が消える
シーンプロパティ > 簡略化 > レンダー 子パーティクル が 0 ヘアや子パーティクルが消える

Child Particles: “Show only a subset of all child hairs and particles.”

（子ヘア／子パーティクルの一部だけを表示する）

原因8簡略化（Simplify）のレンダー側がオンになっている

シーンプロパティ > 簡略化 のレンダー列は、最終レンダーだけに効く。

設定 マニュアルの定義 影響
最大再分割 “Maximum number of subdivision by the subdivision surface modifiers.” 0 にするとサブディビジョンが効かず形が変わる
子パーティクル “Show only a subset of all child hairs and particles.” ヘア／子パーティクルが減る・消える
テクスチャ制限 “Automatically scales textures down…” テクスチャがぼける
AO バウンス “Replace global illumination with ambient occlusion after the specified number of bounces.” 間接光が変わる

レンダービューは「ビューポート」列、F12 は「レンダー」列を見るので、片方だけ崩れる原因になる。

Remember覚えておくべき原則

レンダービュー ＝ ビューポート側の設定で評価。F12 の最終レンダー ＝ レンダー側の設定で評価。

だから「レンダービューでは見えるのに出ない」は、ほぼ必ず「レンダー専用設定（カメラアイコン／簡略化のレンダー列）」か「キャッシュ」のどちらかである。
