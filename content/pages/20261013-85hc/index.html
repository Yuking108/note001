パーティクルがレンダリングに出ない（レンダービューでは見えている）

レンダービューでは出ているのに F12 の最終レンダーで消える。これはレンダー専用の設定（カメラアイコン・簡略化のレンダー列）か、キャッシュのどちらかで、ほぼ決まっている。

結論：最有力は「エミッターをカメラアイコンで隠している」。

パーティクルはエミッターオブジェクトの評価結果の一部。エミッター自体を最終レンダーから外すと、そこから出るパーティクルも一緒に消える。しかもレンダービューはその設定を無視する仕様なので、ビューポートでは正常に見えてしまい気づけない。

エミッターのメッシュだけを隠したいなら、カメラアイコンではなくパーティクルプロパティ > レンダー > 「エミッターを表示」をオフ。これが本来の専用スイッチ。

Principleなぜ「レンダービューでは見える」のか

Blender の表示設定はビューポート用とレンダー用の2列に分かれていて、レンダービュー（ビューポートのレンダープレビュー）はビューポート側の列で評価される。F12 の最終レンダーだけがレンダー側の列を見る。

Show in Renders: “The object is able to be in the final render, note that it will still be visible in rendered shading view.”

（最終レンダーに含めるかどうか。レンダーシェーディングビューには残り続けることに注意）

この一文が症状の正体。あわせて隠したいものは専用のスイッチで隠すという原則を覚えておく。エミッターを隠したいなら「エミッターを表示」オフで、カメラアイコンではない。

Checkチェック順（この順番で見れば必ず見つかる）

  1. エミッターのカメラアイコン（レンダー）がオフになっていないか？

    オンに戻し、代わりに パーティクルプロパティ > レンダー > 「エミッターを表示」をオフ。→ 原因1

  2. モディファイアの「ParticleSystem」のカメラアイコンがオフでないか？

    → 原因2

  3. パーティクルプロパティ > レンダー > レンダー方法 が「なし」でないか？

    → 原因3

  4. シーンプロパティ > 簡略化 > レンダー > 子パーティクル が 0 でないか？

    → 原因4

  5. 発生のフレーム範囲／寿命の中をレンダリングしているか？

    → 原因5

  6. 途中フレームからの書き出し・ターミナルレンダリングなら 物理プロパティ > キャッシュ > ベイク を実行。

    → 原因5

  7. インスタンス元は「目アイコン」で隠しているか？

    モニターアイコンだとビューポートから消える。→ 原因6

Causes原因ごとの詳細

原因1エミッターを「カメラアイコン」で隠している ← 最有力

パーティクルはエミッターオブジェクトの評価結果の一部なので、エミッターが最終レンダーから外れるとパーティクルも一緒に消える。発生元の板や球は消えるが、パーティクルも消える——そしてレンダービューでは両方見えたままになる。

  • アウトライナーの カメラアイコン をオフ
  • オブジェクトプロパティ > 可視性 > 表示 > レンダー のチェックを外す
  • パーティクルプロパティ > レンダー > 「エミッターを表示」をオフ

Show Emitter: “When turned off, the emitter is not rendered.”

（オフにするとエミッターはレンダーされない）

これならエミッターのメッシュだけが消え、パーティクルは残る。

原因2パーティクルシステムモディファイアのカメラアイコンがオフ

パーティクルシステムはモディファイアプロパティに ParticleSystem として並ぶ。そのヘッダーのアイコン列は、オブジェクトレベルとまったく同じ構造の罠になっている。

アイコン 意味
モニター ビューポートで表示（レンダービューもこれに従う）
カメラ レンダーで表示。オフだとレンダービューには出るが F12 で消える

オブジェクト側を直しても出ないなら、モディファイア側も確認する。

原因3レンダー方法が「なし（None）」になっている

パーティクルプロパティ > レンダー > レンダー方法 を確認。オブジェクト／コレクションをインスタンスするつもりで「なし」のまま、というのはよくある。

None: “Particles are not rendered, which is useful when particles only duplicate objects.”

（パーティクルはレンダーされない。パーティクルがオブジェクトを複製するだけの用途に便利）

混同注意：ビューポート表示側の「なし」は意味が違う。“The particles are not shown in the 3D View and are not rendered.” ＝ 両方消える。

原因4簡略化（Simplify）の「レンダー」列で子パーティクルが絞られている

シーンプロパティ > 簡略化 > レンダー > 子パーティクル。

Child Particles: “Show only a subset of all child hairs and particles.”

（子ヘア／子パーティクルの一部だけを表示する）

  • 0 にするとヘアや子パーティクルがレンダーから消える
  • 「レンダー」列は F12 だけに効く（レンダービューは「ビューポート」列を見る） → 「レンダービューでは見えるのに出ない」と完全に一致する
  • 簡略化パネル自体のチェックがオンになっていないかも確認

原因5キャッシュ／フレーム範囲（パーティクルは時間方向のシミュレーション）

シミュレーションは Start と End の間の正のフレームでのみ計算される。

ベイクを推奨：再シミュレーションを避け、グリッチを防ぎ、結果が毎回まったく同じになることを保証できる。

症状が出る典型パターン なぜ出ないか
途中フレームからアニメーションを書き出した（例：100〜200） 1〜99 が未計算なのでパーティクルが発生していない
ファイルを開き直した／別マシンでレンダリング メモリ上のキャッシュが消えている
ターミナル（バックグラウンド）からレンダリング GUI 再生がないのでキャッシュが作られない → ベイクが事実上必須

対策は 物理プロパティ > キャッシュ > ベイク を実行してからレンダリングすること。

あわせて次も確認する。

  • 発生（Emission）> フレーム開始 / 終了 と 寿命（Lifetime） — その範囲外のフレームをレンダリングしていないか
  • レンダー > エクストラ の 未誕生（Unborn）/ 死亡（Dead） のチェック — 誕生前・死亡後のパーティクルを出す／出さないの設定

Not it原因6：これは原因では「ない」（インスタンス元の隠し方）

オブジェクト／コレクションをインスタンスしている場合、インスタンス元の隠し方は挙動が逆になる。

blender#81973（2.91 時点）: “When the instance object of a particle system is disabled in the viewport the particles are also disabled in the viewport. However when the instance object is disabled in render they still appear in the render.”

（インスタンス元をビューポートで無効にするとビューポートのパーティクルも消える。しかしレンダーで無効にしてもパーティクルはレンダーに出る）

インスタンス元の隠し方 パーティクルへの影響
カメラアイコン（レンダーで無効） レンダーには出る ＝ 今回の原因ではない
モニターアイコン（ビューポートで無効） ビューポートからパーティクルも消える（逆の症状）
目アイコン 影響しない ＝ 安全

開発者スレッドでの推奨: “Use that Eye button instead of the Screen button to hide Sphere and everything will be fine.”

（モニターアイコンではなく目アイコンで隠せば問題ない）

2.91 時点の報告でステータスは Confirmed（「ビューポートとレンダーの挙動は一致させるべき」と議論中）なので、バージョンによって変わる可能性がある。目アイコン運用なら影響を受けない。

Opposite逆のケース（間違いやすい）

ビューポート表示 > 量（Amount） はビューポートだけを減らす設定。

“Specifies the percentage of all particles to show in the viewport (all particles are still rendered).”

（ビューポートに表示する割合。レンダーでは全パーティクルが出る）

これは「ビューポートでは少ないのにレンダーで大量に出る」側の原因。今回とは逆なので、ここをいじっても症状は直らない。
