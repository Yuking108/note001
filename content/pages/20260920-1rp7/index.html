iframe sandbox と CSP で本文を隔離する

生成された HTML に JS を許しつつ、アプリ本体を壊させない構成。note001 が実際に使っている設定と、その理由。

二重の境界

本文 HTML は React ツリーに入れず、public/pages/ から iframe で読み込む。境界は2つある。 sandbox が内側から外（アプリ）への手出しを止め、CSP が内側から外（ネットワーク）への通信を止める。

sandbox に何を許すか

<iframe
  src="/pages/20260920-1rp7/index.html"
  sandbox="allow-scripts allow-popups allow-popups-to-escape-sandbox"
></iframe>
トークン 理由
allow-scripts 許可 図解やインタラクティブな説明を動かすため
allow-popups 許可 外部リンクを別タブで開ける。本文が外部ページに置き換わるのを防ぐ
allow-popups-to-escape-sandbox 許可 開いた先のタブに sandbox を継承させない（外部サイトが壊れて見えるのを防ぐ）
allow-same-origin 付けない アプリの DOM・localStorage・Cookie に触れられなくする
allow-forms 付けない 本文にフォーム送信をさせる理由がない
allow-modals 付けない alert() が画面を止めるのを防ぐ
allow-top-navigation 付けない 本文がアプリ全体を別ページへ飛ばせないようにする
allow-scripts と allow-same-origin を同時に付けてはいけない

両方付けると、枠内の文書は親と同一オリジンになり、親の DOM 経由で自分の sandbox 属性を書き換えて再読み込みできる。つまり sandbox が実質無効になる。

opaque origin が効いてくる場所

allow-same-origin を外すと、枠内の文書のオリジンは opaque（不透明）になる。これは単に「別オリジン扱い」ではなく、 どのオリジンとも一致しない状態で、次の2か所で挙動に効く。

1. CSP の 'self' が使えない

'self' は文書自身のオリジンとの一致で判定される。opaque origin はどの URL とも一致しないため、 img-src 'self' と書いても同居させた画像ファイルは読めない。 そこで note001 の CSP は 'self' を使わず、data: と blob: だけを許す。 

default-src 'none';
img-src data: blob:;
media-src data: blob:;
font-src data:;
style-src 'unsafe-inline';
script-src 'unsafe-inline';
connect-src 'none';
frame-src 'none';
form-action 'none';
base-uri 'none'

結果として、画像は data URI で埋め込む必要がある。外部ホストへの通信は default-src 'none' と connect-src 'none' で全面的に閉じる。

インライン SVG は img-src の制限を受けない。 サブリソースの読み込みではなく、ただのマークアップだから。図解を SVG で直接書けば CSP を緩める必要は一切ない。この記事の図もそれで描いている。

2. postMessage の origin が "null" になる

高さの通知を受ける親側で event.origin を検証しようとしても、送信元が opaque origin なので "null" しか来ない。検証は origin ではなく送信元の window 参照で行う。 

const onMessage = (event) => {
  const frame = frameRef.current;
  // origin ではなく source で送信元を確かめる
  if (frame === null || event.source !== frame.contentWindow) return;
  if (event.data?.type !== 'note001:height') return;
  setHeight(Math.ceil(Number(event.data.height)));
};

高さを親から読めないのも opaque origin のせい（contentDocument が読めない）。 そのため、ビルド時に本文のコピーへ高さ通知スニペットを注入し、内側から ResizeObserver で測って送る形にしている。

meta タグで CSP を書くときの注意

note001 は静的ホスティング前提でヘッダを制御できないため、CSP を <meta http-equiv> で注入している。meta 版では効かないディレクティブがある点に注意する。

  • frame-ancestors、report-uri、sandbox は meta では無視される
  • だから枠の制御は CSP ではなく iframe の sandbox 属性側の責務になる
  • meta は <head> の早い位置に置く。後ろだと先に読み込みが始まった分に効かない

この構成で残るリスク

  • script-src 'unsafe-inline' は必須（本文の JS はインライン）。本文を自分で生成している前提に依存している
  • 枠内で重い JS が走れば、そのタブは重くなる。隔離は「壊さない」保証で「軽い」保証ではない
  • CSP は実行時の防御。ビルド時にも外部参照を検出して警告を出し、二重に気づけるようにしている
