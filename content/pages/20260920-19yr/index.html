note001 の使い方と運用ルール

このページ自身が note001 に入っている最初の知識。ページの作り方・ラベルの付け方・壊れたときの直し方をここにまとめる。

この知識ベースの前提

フォルダは作らない。ページはすべて content/pages/ の直下にフラットに並び、分類はラベルだけで行う。 本文は Claude Code が書いた自己完結 HTML で、アプリ側にエディタは無い。

アプリは読み取り専用

書き込み（ページ生成・ラベル付与）は取り込み工程の責務。画面から編集する機能は作らない。 誤字の修正は content/pages/<slug>/index.html を直接エディタで開いて直す。これが正式な手段。

ページを1枚追加する手順

  1. 器を作る

    slug が採番され、meta.json と本文の雛形ができる。

    npm run new -- --title "ページのタイトル"

  2. 本文を書く

    index.html に自己完結 HTML を書く。CSS・SVG・JS は自由。外部ホストへの参照だけは禁止。

  3. ラベルを決める

    content/labels.json の description を読み、既存ラベルから 3〜7 件の候補を出す。 採否は人が決める。新規ラベルを作るのは、既存で表せないと説明できるときだけ。

  4. meta.json を埋める

    summary と labels を記入する。summary は一覧で中身を判断する唯一の手掛かり。

  5. 確認してコミット

    npm run dev で一覧と詳細を見る。履歴とバックアップは git が担う。

ラベルの付け方

ラベルはスラッシュ区切りの階層パス。異なる軸を並べて付けるのが基本形。

軸 問い 例
技術/ 仕事/ 生活/ 何についての知識か 技術/SQLite
形式/ どういう性質の記述か 形式/手順
状態/ どのくらい信頼できるか 状態/検証中

守ること

  • 親ラベルは暗黙に存在する。技術/SQLite を付けたなら 技術 は付けない。
  • 絞り込みは子孫を含む。技術 を選ぶと 技術/SQLite のページも出る。
  • 深さは3段まで。4段目が欲しくなったら軸の切り方を間違えている。
  • 新規ラベルには必ず description を書く。これが次のラベル選びの判断材料になる。

ビルドが止まったとき

npm run index は壊れたコンテンツを静かに通さない。エラーは全部これのどれか。

エラー 直し方
未登録のラベル content/labels.json に description 付きで登録する。あるいは既存ラベルに寄せる
id とディレクトリ名の不一致 meta.json の id をディレクトリ名に合わせる（ディレクトリ名が正）
<head> / </body> が無い 断片ではなく <!doctype html> から始まる完結した文書にする
日付の形式 YYYY-MM-DD にする

警告（summary が空、ラベルが空、未使用ラベル、外部参照）はビルドを止めない。書きかけを許容するため。

本文 HTML のチェックリスト

  • 外部ホストへの参照がゼロ（CDN・Web フォント・外部画像・fetch）
  • <title> がある
  • 明色・暗色の両方で読める（色の定義を暗色ブロックだけに置かない）
  • 幅 375px で横スクロールが出ない（広い表とコードは内側でスクロール）
  • body に不透明な背景色がある（透明だと iframe 越しに親の色が透ける）
  • 外部リンクは target="_blank" rel="noopener"

やらないこと

  • フォルダを作って分類する（ラベルでやる）
  • アプリに編集機能を足す（ファイルを直接直す）
  • 本文からネットワークを叩く（CSP で遮断される）
  • データベースを持ち込む（Phase 6 に到達するまで前提を崩さない）
