Blender Physics Fluid 2026.09.19

流体シミュレーションが動かない

シミュレーションも設定もファイルも、最初から壊れていなかった。押していないボタンが1つあっただけ。

環境: Blender 5.2 LTS / 参考動画 3.6.3 / ドメインの箱に Sphere（流入口）とボトル

Question

流体シミュレーションが、再生しても出ない／ベイクしても出ない

Answerベイクの工程を1つ飛ばしていた

モジュラーでは「データをベイク」と「メッシュをベイク」が別のボタン。「データをベイク」だけ押して止まっていた。

その状態だと流体の計算自体は終わっているのに水面のメッシュが生成されないので、画面には何も出ない。エラーも警告も出ない。

決め手になった観察は「モジュラーだと出ないが、リプレイだと出る」。リプレイは全工程が自動で走るので出る。この差がすべてを説明した。

Root causeキャッシュタイプの違い

タイプ 挙動 使いどころ
リプレイ 再生すると全工程が自動で走る 作業中・確認用。最終レンダリングには非推奨
モジュラー 工程ごとに手動でベイク。ボタンが分かれている 工程ごとに調整したいとき
全て 1ボタンで全工程を一括ベイク 最終レンダリング前はこれが安全

モジュラーで押す順番

  1. データをベイク流体の基本計算
  2. メッシュをベイクここを忘れる 水面のポリゴン生成。これが無いと画面に何も出ない
  3. ノイズをベイク / パーティクルをベイク必要に応じて

Rules運用ルール

これだけ守れば再発しない。

  • 作業中・確認リプレイ
  • レンダリング前「全て」でベイク
  • 迷ったらモジュラーを使わない（押し忘れが起きる）

Dead ends遠回りの記録

結論に至るまでに疑って外れたもの。同じ沼に入らないために残す。

疑ったこと 結果
表面からの発生距離が 0 → 1.5 に変更 液体は出たが、値そのものが原因とは限らない。設定変更でキャッシュが無効化され再計算が走ったのが効いた可能性が高い。0 は発生範囲が実質ゼロなので 1.5 に戻すこと自体は正しい
Shift+← で1フレーム目に戻す リプレイで古いキャッシュが残っているときには実際に有効。公式バグ #75850 の回避策としても挙げられている
キャッシュのパス / 日本語パス / iCloud 同期 / ディスク容量 今回は無関係
公式バグ #72860 / #85403 / #73770 いずれも該当せず（#73770 は Windows 専用・修正済み）
ドメインタイプが「ガス」のまま / スケール未適用 / 解像度不足 該当せず

Checklist出ないときのチェックリスト

  1. ベイクのボタンが他にもないか見る（モジュラーなら「メッシュをベイク」）— 今回の原因
  2. キャッシュタイプを「全て」にして一括ベイクしてみる
  3. Shift+← で1フレーム目に戻して再読み込みさせる（リプレイのキャッシュが古いとき）
  4. ドメインのドメインタイプが「液体」か（初期値は「ガス」）
  5. フロータイプが「液体」／フローの挙動が「流入口」か（フロータイプの初期値も「煙」）
  6. フローの「表面からの発生距離」が 0 になっていないか（通常 1.5）
  7. ドメインのスケールを適用したか（Ctrl+A > スケール）
  8. 解像度（Resolution Divisions）。初期値 32 では小さい流入口を拾えない
  9. 切り分け：新規ファイルで「クイック液体」が動くか。動けば Blender は正常、ファイル側の問題
原文にあったスクリーンショット4点（講座の見た目 / 自分の見た目 / Sphere の設定）は未取り込み。Sphere 側は「フロータイプ＝液体／フローの挙動＝流入口／フローを使用 ON」で正しかった。

Lessons教訓

「ベイクしたのに出ない」ときは、まずベイクのボタンが他にもないか見る。

設定や環境（パス・同期・ディスク・バグ）を疑う前に、工程の押し忘れを疑う。今回は環境側を延々と調べたが、答えは押していないボタンが1つあっただけだった。

「A だと動くが B だと動かない」という差が見つかったら、それが最短の手がかり。

今回もリプレイとモジュラーの差に気づいた瞬間に解決した。
