# 液体シミュレーションのドメイン設定

ドメインを選択したときの物理演算プロパティの各パネルを、上から順に。**どこを触り、どこを触らなくていいか**の判断が目的。

> 前提として、ドメイン／フロー／エフェクターの役割分担は [[KNOW_流体シミュレーションの3つの役割]] を参照。

## 最初に守るルール

> **実行前に必ず保存する。** 液体シミュレーションはメモリを大量に使い、クラッシュしやすい。解像度を上げたときは特に。

---

## 設定（Settings）

### 解像度（Resolution Divisions）

**ドメインを何分割して計算するか。** 上げるほどディテールが出て、上げるほど重くなる。

- **3Dビューポートに小さなキューブが表示され、それが1ボクセル（計算1マス）の大きさ**を示している。**このキューブが小さいほど解像度が高い**
- 重要な性質として、**分割の基準はドメインの一番長い辺**。つまり**ドメインが大きいほど、同じ数値でも1マスが粗くなる**
  - → だから「ドメインは流体が通る範囲ギリギリまで小さく」が効いてくる。小さくするだけで実質的に解像度が上がる

#### 実用の目安（経験則）

| 値 | 用途 |
| --- | --- |
| 32〜64 | 動きの確認用。粗いが速い |
| **128** | **おすすめ。実用的な品質と速度のバランス** |
| 150〜300 | 仕上げ用。PCの性能次第。ここから先はクラッシュリスクが上がる |

いきなり高解像度で回さず、**低解像度で動きを決めてから上げる**のが鉄則。

### 時間スケール（Time Scale）

シミュレーションの進む速さ。下げるとスローモーション、上げると早送りになる。演出目的以外は触らない。

### CFL数とタイムステップ（最大/最小）

**ここがこのパネルで一番「効く」設定。**

#### CFL数とは

`速度 × (時間刻み ÷ ボクセルサイズ)` で表される**安定条件**。要するに「**1ステップで粒子が1マス以上進まないようにする**」ための指標。理論上は **CFL ≦ 1** が望ましい。

Blenderのデフォルトは **4.0**。これは正確さよりも**ベイク時間の短縮を優先した値**。CFL数が大きいと、速い流体で粒子がマスを飛び越えてしまい、情報が失われる。

#### タイムステップが効く場面

CFL数を超えそうになると、Blenderは自動で**1フレーム内の計算回数（タイムステップ）を増やして**安定させる。その回数の上限・下限がこの2つ。

**上限が足りないと、速い液体が薄い障害物をすり抜ける。** Blender本体にも「デフォルト設定でエフェクターを液体がすり抜ける」問題への修正が入っているほど、起きやすい現象。

| 設定 | 推奨 | 意味 |
| --- | --- | --- |
| タイムステップ **最大** | **8** | 速い流体でも安定させるための余力。上げるとベイク時間が伸びる |
| タイムステップ **最小** | **4** | 毎フレーム最低これだけは計算する。品質の下限を保証する |

デフォルトより高めの「最大8／最小4」は、**速度と安定性を安定性側に寄せた設定**。液体がすり抜ける・暴れる・消えるときは、まずここを上げる。

> ⚠️ CFL数とタイムステップは**セットで調整する**もの。片方だけ触っても意図した結果にならない。また、解像度やフレームレートとも相互に影響し合う。

---

## ボーダーコリジョン（Border Collisions）

**ドメインの6面それぞれを「壁にするか / 素通りさせるか」の設定。**

- **チェックあり** … その面が壁になり、流体がぶつかって跳ね返る
- **チェックなし** … 流体はその面を**通り抜けて消える**

初期状態は**全面が有効（＝閉じた箱）**。

### ⚠️ 「基本的に外してよい」は条件付き

外すこと自体は間違いではないが、**目的次第**なので機械的に外さない。

| 外すべき場面 | 外してはいけない場面 |
| --- | --- |
| ドメインの**見えない床に水が溜まる**のが邪魔なとき | 水を**溜めたい**とき（プール、コップの受け皿など） |
| テーブルの縁から水をこぼして**流し続けたい**とき | 跳ね返りを見せたいとき |
| 流入口を出しっぱなしにして**排水したい**とき | |

**外した面から出た流体は消える**（戻ってこない）という点だけ覚えておけば、判断を間違えない。

---

## 液体（Liquid）

**基本はデフォルトのままでよい。** 中身を知っておくと、詰まったときに効く。

- **シミュレーション方式** … `FLIP`（飛沫が派手）と `APIC`（安定していて渦が残る）
- **パーティクル半径** … 粒子1つが占める範囲。**液体が消えてしまうときは、ここを上げる**
- **ナローバンド幅** … 粒子を計算する帯の厚み。小さいほどディテールが残る
- **端数の障害物（Fractional Obstacles）** … 斜面のギザギザ（階段状のアーティファクト）を軽減する

---

## メッシュ（Mesh）

### なぜメッシュが必要なのか

**Blenderの液体シミュレーションはパーティクル（粒子）ベース。** 水は本質的には粒の集まりで、そのままでは水面にならない。

**メッシュは、その粒子の集まりを包み込んで「水面」というポリゴンを生成する工程。**

```
 粒子の集まり（計算結果）  →  メッシュ生成  →  見える水面
```

- 基本はデフォルトのままでよい
- **アップレス係数（Upres Factor）** … 水面だけを高解像度化できる。シミュレーション本体は128のまま、水面だけ滑らかに、という使い方ができる

> **ここが抜けると「ベイクしたのに何も出ない」になる。** → [[Q&A_流体シミュレーションで液体が出ない]]

---

## キャッシュ（Cache）

### なぜキャッシュが要るのか

流体シミュレーションは**非常に重い**ので、再生のたびにリアルタイムで計算させるのは無理がある。**一度計算した結果をディスクに保存しておき、再生時はそれを読むだけにする**のがキャッシュ（＝ベイク）。

**流体を使うなら、ベイクは必須工程**と考えてよい。

### キャッシュタイプの選択

| タイプ | 挙動 | 評価 |
| --- | --- | --- |
| **リプレイ** | 再生すると全工程が自動で走る | 手軽だが、**解像度を下げないと実用にならない**。確認用 |
| **モジュラー** | 工程ごとに手動でベイク（データ → メッシュ → ノイズ…） | **おすすめ。** 段階的にベイクできるので、調整とトラブル切り分けがしやすい |
| **全て** | 1ボタンで全工程を一括ベイク | 最終レンダリング前に確実に回したいとき |

### ⚠️ モジュラーの落とし穴

モジュラーは**ボタンが工程ごとに分かれている**ため、「**データをベイク**」だけ押して「**メッシュをベイク**」を押し忘れる、という事故が起きる。エラーも警告も出ないまま何も表示されない。

実際にこれでハマった記録 → [[Q&A_流体シミュレーションで液体が出ない]]

**モジュラーを使うなら、押すボタンが他にないか毎回確認する。** 迷ったら「全て」。

---

## 作業手順のまとめ

1. **ファイルを保存する**（クラッシュ対策）
2. ドメインタイプを「液体」に（初期値はガス）
3. ドメインを**必要最小限の大きさ**に縮める
4. 解像度を **32〜64** にして、動きだけ確認
5. 液体がすり抜ける／暴れるなら、タイムステップ **最大8／最小4** に
6. ボーダーコリジョンを目的に合わせて調整（溜めたいか、流したいか）
7. 解像度を **128** に上げて、キャッシュタイプを「モジュラー」または「全て」でベイク
8. **メッシュのベイクを忘れない**
