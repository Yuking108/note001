# アニメーションのフレーム設計とオーバーラップ（遅延）

チュートリアルで出てきた「24フレーム単位で考える」「アニメーションの遅延を使う」という2つのテクニックを、裏取りしたうえで言語化したもの。

## 目的

素人っぽいアニメーション（動きが等間隔で機械的／カメラが止まってから被写体が動き出してブツ切れになる）を、流れのあるプロっぽいアニメーションにする。

---

## 1. フレームは「1秒 = 24フレーム」で考える

### 結論：正しい。前提として必ず押さえる

- 映画の標準フレームレートが 24fps で、**Blenderのデフォルトも 24fps**（出力プロパティ > フォーマット > フレームレート）。デフォルトの終了フレーム 250 は、24fps でおよそ10秒にあたる。
- つまり **フレーム数 ÷ 24 = 秒数**。24 = 1秒、48 = 2秒、12 = 0.5秒、6 = 0.25秒。
- 「何フレームか」ではなく「**何秒に見えるか**」で判断するクセをつける。fps を 30 や 60 に変えたら、同じ見え方にするにはフレーム数も換算し直す必要がある。

### 「24の倍数で区切るとよい」の正しい解釈

ここは **言い方によって正しくも間違いにもなる** ので注意。

| 解釈 | 判定 | 理由 |
| --- | --- | --- |
| 尺・カット・演出の「区切り」を秒単位（24の倍数）で設計する | ⭕ 正しい | 秒で考えられるので尺の計算が楽。音・カット割り・ループと合わせやすい |
| アニメーション内の**すべてのキーフレーム**を24の倍数に置く | ✕ 間違い | 全部が等間隔になり、機械的・ロボット的な動きになる |

後者はアニメーションの世界で **"even spacing syndrome"（等間隔症候群）** と呼ばれる典型的な失敗。「各フレームが同じ距離だけ動くと、ショットはロボットのように見える」とされている。

> **使い分け**
> - **マクロ（全体の尺・カットの区切り・ブロックの長さ）** → 24の倍数で気持ちよく設計してよい
> - **ミクロ（1つの動きの中のキー間隔、次の動きの開始タイミング）** → 24の倍数から意図的に外す。特に次の動きの開始は、下の「オーバーラップ」で数フレーム手前にずらす

---

## 2. アニメーションを「オーバーラップ（重ねる）」させる

### 結論：正しい。これが「遅延」の正体

チュートリアルでいう「遅延」とは——

> **カメラのアニメーションが終わる数フレーム前に、被写体のアニメーションを開始する。**

つまり「間を空ける」のではなく、**前の動きが完全に止まりきる前に次の動きを始めて、2つを重ねる**ということ。英語圏では **overlapping action（オーバーラッピングアクション／オーバーラップ）** と呼ばれ、アニメーション12原則の「フォロースルーとオーバーラッピングアクション」にあたる。

### なぜ効くのか（言語化）

1. **デッドストップ（完全停止）を作らない**
   カメラが止まる → 何も動かない瞬間ができる → 被写体が動き出す、という順番だと、動きがブツ切れになる。「1つのアクションが完全に止まってから次が始まる」厳密な逐次進行こそが、機械的・人工的に見える原因とされている。

2. **モメンタム（勢い）が次の動きに引き継がれる**
   現実の物体には慣性があり、動きは途切れずに次へ繋がる。タイミングをずらして重ねることで、重さや質量が伝わり、物理的に地に足のついた動きになる。

3. **カメラのイーズアウト区間の「死んだ時間」を埋められる**
   カメラは終わり際に減速する（イーズアウト）ので、最後の数フレームはほとんど絵が変わらない。ここで被写体を動かし始めると、その空白が埋まり、**カメラが止まったことが観客に気づかれなくなる**。

4. **視線が自然に受け渡される**
   カメラの動きから被写体の動きへ、注目が途切れずにバトンタッチされる。

### 具体的なタイミング

```
【NG：デッドストップ】
カメラ  : 1 ──────────── 48F
被写体  :                  49 ──────── 96F
          ↑ 48Fと49Fの間で動きが一度死ぬ。ブツ切れ・素人っぽい

【NG：完全同時】
カメラ  : 1 ──────────── 48F
被写体  : 1 ──────────── 48F
          ↑ 両方同時に動くので、どちらも読めない

【OK：オーバーラップ】
カメラ  : 1 ──────────── 48F
被写体  :              42 ──────────── 90F
          ↑ カメラが減速している数フレーム間に被写体が動き出す
```

- **目安は数フレーム〜十数フレーム**（24fpsで 3〜12F 程度）。カメラの**イーズアウト（減速）区間に食い込ませる**のがコツ。
- 重ねすぎると「完全同時」に近づき、両方の動きが読めなくなる。**カメラの動きの主要部分（大きく絵が変わる部分）は終わっていること**が条件。
- 逆に数フレームしか重ねないと効果が薄い。再生して「止まった感じ」が消えるまで調整する。

### 補足：「間（ため）を置く」テクニックとの違い

別のテクニックとして「ポーズを見せるために動きを一瞬止める（ホールド／ビート）」というものもあり、これも正しい。ただし**目的が逆**なので混同しないこと。

| | オーバーラップ（本項） | ホールド／間 |
| --- | --- | --- |
| やること | 次の動きを前倒しして重ねる | 動きを止めて保持する |
| 目的 | 流れ・勢いを途切れさせない | ポーズや情報を読ませる |
| 使う場面 | カメラ→被写体など、動きを繋げたいとき | 見せ場、演出の区切り、情報の切り替え |

## Blenderでの実作業メモ

- **被写体のキーをまとめて前にずらす** — ドープシートで被写体のキーを全選択 → `G` → `-6` → `Enter` で6フレーム手前へ。これがオーバーラップ調整の基本操作。
- **どこから重ねるか判断する** — グラフエディターでカメラのFカーブを見て、**傾きが寝てくる（減速に入る）あたり**を被写体の開始フレームにする。数字で決めるより、カーブを見たほうが早い。
- **秒表示に切り替える** — タイムライン／ドープシートの ビュー > 秒 をON。尺の設計は秒で、重ねる量はフレームで、と見方を使い分ける。
- **fpsの確認を最初に** — 出力プロパティ > フォーマット > フレームレート。24以外（30/60）にするなら、上のフレーム数は全部換算し直す。
- **イーズの掛かり方も効く** — オーバーラップの気持ちよさは、カメラ側のイーズアウトの効き具合に左右される。グラフエディターでハンドルを調整して、減速区間の長さ自体もコントロールする。

## 注意点

- 24の倍数に**スナップさせすぎない**。特に次の動きの開始フレームは、意図的に倍数から外すことになる。
- 上に挙げたフレーム数は **"starting points, not laws"（出発点であって法則ではない）**。必ず再生して目で確認し、動きの大きさ・速度に合わせて詰める。
- オーバーラップは**カメラと被写体に限らない**。オブジェクトA→オブジェクトB、本体→付属物（布・髪・アンテナなど）でも同じ考え方が使える。
