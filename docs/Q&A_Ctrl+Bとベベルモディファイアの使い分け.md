# Q. ベベル後の編集では Ctrl+B のベベルは使わないの？ベベルモディファイアは全体にかかるのでは？

## A1. ベベルモディファイアは「全体にかかる」わけではない

制限方法（Limit Method）で、どの辺にかけるかを完全にコントロールできる。ここを理解すると使い勝手が変わる。

| 制限方法 | 挙動 |
| --- | --- |
| **なし（None）** | 全部の辺にかかる。これが「全体にかかる」状態 |
| **角度（Angle）** | 既定30°。設定角度より鋭い辺だけ。平らに繋がっている部分は無視される |
| **ウェイト（Weight）** | ベベルウェイトが0より大きい辺だけ。**辺ごとの完全な指名制** |
| **頂点グループ** | 頂点グループに含まれる部分だけ |

つまり「狙った辺だけベベル」は**ウェイト**でできる。既定が「角度」なので何もしなくても平面部分は落ちない。

### ウェイトの付け方

1. 編集モードで辺を選択
2. Ctrl+E → **ベベルウェイト** でドラッグして1にする
   （またはNパネル → アイテム → 辺データ → 平均ベベルウェイト に直接1を入力）
3. モディファイアの制限方法を「ウェイト」に

### ウェイトは幅の倍率にもなる

制限方法がウェイトのとき、ベベル幅は**辺のウェイト値で掛け算される**。ウェイト1の辺は指定幅どおり、0.5の辺は半分の幅。
→ 1つのモディファイアで「太い面取り」と「細い面取り」を作り分けられる。

さらに細かく分けたいときは、ベベルモディファイアを2つ以上重ね、それぞれ別の頂点グループで制限する。

## A2. Ctrl+B（破壊的ベベル）も普通に使う。使い分けの基準がある

前のノートの「編集中はモディファイアで持つ」は、**見た目の角の丸みが目的の場合**の話。Ctrl+B が正解の場面はちゃんとある。

### 判断基準

> **ベベルで出来た面の上に、さらにモデリングを続ける必要があるか？**
>
> - 続ける → **Ctrl+B**（実体のあるジオメトリが必要）
> - 角を丸めたいだけ → **モディファイア**

### Ctrl+B を使う具体的な場面

- 面取りした面に**穴を開ける・押し出す・別のディテールを乗せる**
- サブディビジョンサーフェス前提の**サポートエッジ（コントロールループ）**を意図した位置に入れる
- 辺ループを増やす手段として使う（分割の代用）
- **頂点ベベル（Ctrl+Shift+B）**で角を落とす
- モディファイアが破綻する**複雑な交差部分**を手で処理する
- スカルプト / リトポ / ゲーム書き出しなど、**メッシュを確定させる**段階
- プロファイル（断面カーブ）を凝って、その形を実体として持ちたいとき

### 逆にモディファイアが向く場面

- 最後の仕上げとしての面取り・角丸
- 幅や段数を**後から何度も調整したい**
- ベースの形をまだ触る（辺を動かす・比率を変える）
- 同じ設定を複数オブジェクトに使い回す（コピー / リンク）

## 実務的な組み合わせ方

多くの場合は併用する。

1. Ctrl+B は**形を作るため**に使う（構造としての面取り、サポートループ）
2. 最終的な**見た目の角丸**はベベルモディファイアに任せ、辺にウェイトを付けて指名する
3. 書き出しが必要になった時点でモディファイアを適用（複製をバックアップに残す）

## まとめ

- 「ベベルモディファイア＝全体にかかる」は誤解。制限方法が既定で角度、ウェイトにすれば辺ごとの指名制
- Ctrl+B は禁止ではない。**ベベル後の面の上に作業を続けるなら Ctrl+B**、**角を丸めるだけならモディファイア**
