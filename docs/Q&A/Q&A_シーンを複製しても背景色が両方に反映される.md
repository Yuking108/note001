# Q. シーンをコピーしたのに、背景だけは色を変更すると別のシーンにも反映される

オブジェクトやカメラは独立しているのに、ワールドの背景色だけ両方のシーンで一緒に変わってしまう。

## A. ワールドは「シーンの中身」ではなく、シーンが参照している別データだから

Blenderのデータ構造は **データブロック** という単位の**参照関係**でできている。

```
シーンA ──┐
          ├──> ワールド ──> 背景色
シーンB ──┘
```

シーンを複製しても、**複製されるのは「シーンという箱」だけで、箱が指している先のワールドは同じまま**というケースがある。2つのシーンが**同じ1つのワールドを見ている**ので、片方で色を変えれば当然もう片方にも出る。

バグでも設定ミスでもなく、**データブロックの共有**という仕組みどおりの挙動。

---

## 見分け方：名前の横の数字

ワールドプロパティで、ワールド名の横に **「2」などの数字**が出ていないか見る。

> **その数字は「このデータを使っている数（ユーザー数）」。**
> **数字が出ている ＝ 共有されている。**

## 直し方：その数字をクリックする

数字ボタンをクリックすると、**単一ユーザーのコピー**になる。以後、そのシーンのワールドを変えても他のシーンには影響しない。

### データブロック欄の各ボタン

| ボタン | 動作 |
| --- | --- |
| **数字** | **クリックで単一ユーザーのコピーを作る**（今回の解決策） |
| 新規 | 新しいデータブロックを作る／現在のものを複製して適用する |
| ブラウズ（左のアイコン） | ファイル内の既存データブロックから選ぶ |
| シールド（フェイクユーザー） | 使われていなくてもファイルに保存し続ける |
| X | 参照を外す |

---

## なぜ共有されるのか：新規シーンの4つの作り方

| 種類 | 内容 |
| --- | --- |
| **新規** | 既定値の空のシーン |
| **設定をコピー** | 空だが、アクティブシーンの設定だけ引き継ぐ |
| **リンクコピー** | 同じ設定・内容の新シーン。ただし**オブジェクトは複製されず、元のコレクションを参照する**。→ **どちらで編集しても両方に効く** |
| **完全コピー** | 「**何も共有しない**」。オブジェクトとそのデータをすべて複製する |

**リンクコピーは、共有すること自体が目的の機能。** 意図せず選んでいると今回のような混乱になる。

> ⚠️ ただしワールドについては、**どの方法で作ったかを思い出すより、名前の横の数字を見るほうが確実**。

---

## 背景が「板（平面オブジェクト）」の場合

背景がワールドではなく背景用の平面だった場合も、同じ話がもう一段ある。

- **リンクコピー**ではオブジェクト自体が共有される → 動かしても両方に効く
- **マテリアルも独立したデータブロック** → 別オブジェクトでも同じマテリアルを参照していれば、色変更は両方に出る

→ マテリアルプロパティでも同様に、**名前の横の数字をクリック**して単一ユーザー化する。

---

## 覚えておく原則

> **Blenderで「片方を変えたら両方変わった」は、ほぼ全部データブロックの共有が原因。**
> **まず名前の横の数字を見る。**

これはワールドだけの話ではなく、**マテリアル・メッシュ・アクション・ノードグループ・テクスチャ**すべてに共通する。逆に言えば、この仕組みを理解すると「1つ直せば全部直る」という使い方も意図的にできるようになる。
