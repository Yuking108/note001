# Q. 古いチュートリアルの「パワー 2000W」を今のバージョンで入れても明るさが全然違う

## A. 見た目が違うのは正しい。ただし「W の意味」が変わったわけではない

> **【実例・2026-10-03 に実際に遭遇したケース】**
> 教科書通りに 2000 を入れたら白飛びした。**原因はシーンのスケールだった。**
> 全体が想定より小さく作られていたため、ライトとの距離が近すぎて光を受けすぎていた。
> → 詳しくは「原因4」。**ライトが合わないと感じたら、まずスケールを疑うこと。**


**パワーの単位も、数値が表す物理量も変わっていない。** 2000 W は昔も今も 2000 W。

変わったのは**その光を画面に映すまでの過程**と、**シーン側の条件**。原因は大きく5つあり、どれも「数値を合わせても絵が合わない」結果になる。

## 原因0: Blender 4.5 でライトのUIが変わった（まず最初に確認）

**Blender 4.5 でライトの設定が大きく変わった。** 5.x もこれを引き継いでいる。

### 「W」の表示が消えた — ただし数値の意味は同じ

4.5 で**パワー欄から「W」の単位表示が削除された。**

公式リリースノートの理由: 現実のライトは光束（ルーメンなど）の測光単位で表記されるのが普通で、Blender の「W」はそれとは別物だったため、**混乱を招くという理由で表示をやめた。**

**値そのものは変わっていない。** 現在の `200` は、昔の `200 W` と同じ明るさ。チュートリアルの数値はそのまま入れてよい。

### 新しく増えた2つの項目 ← 白飛びの原因はここ

| 項目 | 内容 |
| --- | --- |
| **露出（Exposure）** | ライトの明るさを **2^露出** 倍する。露出 1 で2倍、2 で4倍、3 で8倍。**パワーとは別に掛かる** |
| **温度（Temperature）** | 黒体放射で色を指定。カラーと掛け合わされる |
| **正規化（Normalize）** | オフにすると、**明るさが面積で割られなくなる**。ライトを大きくすると明るさも増える挙動になる |

**チュートリアル通りのパワーを入れたのに白飛びする場合、まず「露出」が 0 かどうかを見る。** 露出が 3 入っていれば、それだけで8倍の明るさになる。

同様に**正規化がオフ**になっていると、エリアライトのサイズ次第で桁違いに明るくなる。

### 確認する場所

ライトのオブジェクトデータプロパティ（緑の電球アイコン）

- パワーのすぐ下 → **露出**
- 「発光の形状」パネルの中 → **広がり（Spread）**、**正規化**

## 原因1: ビュー変換が Filmic から AgX に変わった

**Blender 4.0 でデフォルトのビュー変換が Filmic から AgX に変更された。**

AgX はハイライトの粘りと彩度の落とし方が Filmic と大きく違うため、**まったく同じライト設定でも、明るさ・コントラスト・色の出方が別物になる。**

3.x 世代のチュートリアルを見ているなら、これが主因である可能性が高い。

**確認・対処**: レンダープロパティ > カラーマネジメント > **ビュー変換**

- チュートリアルが 3.x 世代 → 試しに **Filmic** にすると近づく
- 作り直すなら AgX のままで、**数値ではなく見た目で合わせる**ほうがよい

> **白飛びしている場合は Filmic にしないこと。** Filmic は AgX よりハイライトのクリップが早く、**白飛びを悪化させる。** AgX は白飛び手前で長く粘る設計なので、ハイライトを救いたいなら AgX のままにする。
>
> Filmic が有効なのは「暗い・コントラストが浅い」ときに昔の絵へ寄せる場合。

→ [[KNOW_AgXとカラーマネジメント]]

## 原因2: EEVEE が別物になった

**Blender 4.2 で EEVEE が EEVEE Next に置き換わった（内部的に完全な作り直し）。**

旧 EEVEE は物理的に正確なライティングではなかったため、同じワット数でも明るさ・減衰・影の出方が現在とは違う。チュートリアルが旧 EEVEE なら、数値は参考にならない。

**確認**: レンダープロパティ > レンダーエンジン（Cycles か EEVEE か）。チュートリアルと同じエンジンか確認する。

## 原因3: エリアライトは「サイズ」で明るさが変わる

**パワーはライト全体の総ワット数。** エリアライトの場合、その総量が**ライトの面積に広がる**。

- サイズが**大きい** → 同じ W でも**1点あたりは暗く**、影は柔らかい
- サイズが**小さい** → 同じ W でも**明るく**、影は硬い

チュートリアルがサイズを映していないことは多い。**W だけ合わせてもサイズが違えば結果は合わない。**

## 原因4: シーンのスケール（逆二乗の法則）← 実際の原因はこれだった

### 法則

```
明るさ ∝ パワー ÷ 距離²
```

光は**距離の2乗に反比例して弱くなる。** つまり**シーン全体の大きさが変われば、同じワット数でも明るさがまったく変わる。**

| シーンの大きさ | 同じパワーでの明るさ | 同じ見た目にするのに必要なパワー |
| --- | --- | --- |
| 1/10 の大きさ | **100倍 明るい** | 1/100 |
| 1/2 の大きさ | **4倍 明るい** | 1/4 |
| 2倍の大きさ | 1/4 の明るさ | 4倍 |
| 10倍の大きさ | 1/100 の明るさ | 100倍 |

**スケールを k 倍にしたら、同じ見た目にはパワーが k² 倍必要。**

### 白飛びするなら「シーンが小さすぎる」

**シーンが小さい = ライトとの距離が近い = 光を受けすぎる。** チュートリアルの数値をそのまま入れて白飛びするなら、自分のシーンがチュートリアルより小さく作られている可能性が高い。

逆に「暗すぎる」ならシーンが大きすぎる。

### 直し方

**A. シーン全体を実寸に合わせる（おすすめ）**

オブジェクトモードで全部選択 → `S` で拡大/縮小 → `Ctrl+A` > スケールを適用。

実寸に合わせておけば、チュートリアルの数値がそのまま使えるようになるうえ、**被写界深度・物理演算・流体シミュレーションもすべて実寸前提**なので、後々のトラブルがまとめて減る。

**B. パワーを下げる（手っ取り早い）**

見た目が合えばそれでよい場面ならこちら。ただし**スケールのズレは残る**ので、物理演算や被写界深度を使う段階で再び問題になる。

### 予防: 最初から実寸で作る

`N` パネルの**「寸法（Dimensions）」**を見ながら作る。目安:

| もの | 実寸 |
| --- | --- |
| デフォルトのキューブ | 2 m |
| 人の身長 | 約 1.7 m |
| A4 用紙 | 0.21 × 0.297 m |
| ドア | 約 0.9 × 2.0 m |
| スマートフォン | 約 0.07 × 0.15 m |

最初に1つ実寸の基準オブジェクトを置いてから作り始めると、スケールがずれにくい。

## 原因5: 露出（Exposure）

レンダープロパティ > カラーマネジメント > **露出** が 0 以外になっていると、ライトとは別に全体が明るく/暗くなる。

## 結論: 数値を合わせにいかない

チュートリアルのワット数は、**そのチュートリアルのシーンスケール・ライトサイズ・距離・エンジン・カラーマネジメントが全部揃って初めて意味を持つ値**。数値の一致を目指すのは筋が悪い。

### 実務的なやり方

1. チュートリアルの数値を**出発点**として入れる
2. **ビューポートのレンダープレビュー**を見ながら、自分のシーンで納得いく明るさまで調整する
3. 暗すぎるときは、まず**ライトの距離とサイズ**を確認してからワット数を上げる

## 確認チェックリスト

| 項目 | 場所 |
| --- | --- |
| **ライトの露出** | ライトのオブジェクトデータプロパティ（パワーの真下） |
| **正規化** | ライトのオブジェクトデータ > 発光の形状 |
| ビュー変換（AgX / Filmic） | レンダープロパティ > カラーマネジメント |
| 露出 | 同上 |
| レンダーエンジン | レンダープロパティ |
| ライトのサイズ | ライトのオブジェクトデータプロパティ |
| ライトまでの距離 | N パネルの位置 |
| **シーン全体のスケール（実寸か）** | **N パネルの「寸法」。まずここを疑う** |
