# カメラを動かすかオブジェクトを動かすか

## ひとことで

**好みの問題ではなく、ショットごとに答えが決まる。** 判断材料は「何が主役か」「ライティングがどう見えるか」「物理シミュがあるか」「モーションブラーをどう出したいか」の4つ。迷ったら**カメラを動かすほうが安全**。

最終的な絵は「カメラと被写体の相対的な動き」で決まるので幾何的には同じに見えるが、**ライティング・物理・ブラーはワールド座標基準で計算される**ため、実際の結果は別物になる。ここが本質。

## 判断の軸

### 1. 主役はどちらか

| 見せたいもの | 動かすもの |
| --- | --- |
| 空間の広がり、スケール、位置関係、周囲の状況 | **カメラ** |
| そのものの動き（歩く / 落ちる / 開く / 壊れる） | **オブジェクト** |

「部屋を見せたい」ならカメラ。「ドアが開くのを見せたい」ならオブジェクト。

### 2. ライティングと反射 ← 一番差が出るところ

**ライトとHDRIはワールド座標に固定されている。**

- **オブジェクトを回す**: ハイライトと反射が表面を流れていく。金属や光沢のある素材だと「回っている」感が強く出るが、面ごとに明るさが変わるのでチラつくこともある
- **カメラを回す**: 被写体に対するライティングが固定されるので、陰影が安定して見える

製品のターンテーブル動画は、**カメラを回すほうが一般的**（ライティングが一定になるため）。逆に「実写スタジオで回転台に乗せた質感」を狙うなら、オブジェクトを回すほうが正しい。

### 3. 物理シミュレーションがあるか

リジッドボディ / クロス / 流体 / パーティクル / ヘアは、**オブジェクトを動かすと挙動そのものが変わる**。意図しない慣性や風圧が発生する。

→ **シミュレーションがあるならカメラを動かす。** オブジェクトを動かす場合は、それを「演出」ではなく「シミュレーションへの入力」として設計する必要がある。

### 4. モーションブラー

- **オブジェクトを動かす**: 被写体だけがブレて、背景は止まる
- **カメラを動かす**: 背景も含めて画面全体が流れる

同じ相対運動でも**まったく別の絵**になる。ここは幾何的に等価にならない代表例。

### 5. 影

オブジェクトを動かすと影も一緒に動く。床に落ちた影が動くかどうかで印象が大きく変わるので、カットの狙いに合わせて選ぶ。

## 実務的なテクニック

- **カメラを直接動かさず、Empty を親にして Empty を動かす / 回す**。回転中心が安定し、あとから軌道だけ差し替えられる
- **Track To コンストレイント**でカメラを常に被写体（Empty）に向けておくと、軌道だけ考えればよくなる
- カーブに沿わせたいなら **Follow Path コンストレイント**
- 「カメラを回す」と「被写体を回す」を同時にやると、実写では撮れない絵になる。モーショングラフィックス的な表現で使われる

## 結論

人によるのではなく、**ショットの目的とシーンの構成（ライティング・物理）で決まる**。強いて原則を挙げるなら:

1. シミュレーションがある → カメラ
2. 空間や状況を見せたい → カメラ
3. そのものの動きが主題 → オブジェクト
4. 製品を見せる → 基本カメラ（回転台の質感を狙うならオブジェクト）
