# AgXとカラーマネジメント

レンダープロパティの「カラーマネジメント」パネルが何をしているのか、なぜAgXだと眠く見えるのかの理解。

## 概要

Cyclesが計算した結果は、明るさに上限のない**リニアなHDRデータ**。一方ディスプレイが表示できる範囲は限られている。カラーマネジメントは、この **HDR → 表示可能な範囲** の変換を担当する。

「レンダリングが暗い／眠い／色が飛ぶ」は、ライティングの問題ではなく**この変換の問題**であることが多い。

## パネルの各項目の役割

| 項目 | 役割 |
| --- | --- |
| **表示（Display Device）** | 出力先のディスプレイの種類。通常は `sRGB` |
| **ビュー（View Transform）** | HDR→SDRの変換方式そのもの。**ここが一番大きく絵を変える** |
| **ルック（Look）** | ビュー変換の上に掛ける、コントラスト調整のプリセット |
| **露出（Exposure）** | 変換前に明るさを底上げ／減光する |
| **ガンマ（Gamma）** | 変換前のガンマ補正 |

## ビュー変換の選択肢

- **標準（Standard）** … 変換なしに近い。明るい部分が白にベタ潰れする
- **Khronos PBR Neutral**
- **AgX** … Blender 4.0からのデフォルト
- **Filmic** … 3.x時代のデフォルト
- **Filmic Log**
- **False Color** … 明るさを色分けして可視化するデバッグ用
- **Raw**

## なぜAgXは彩度が低く見えるのか

AgXは **明るくなるほど彩度を落とす** 設計になっている。

これは **ヒュースキッディング（hue skidding）** を避けるため。「標準」だと、明るい赤や青が表示範囲を超えた瞬間に色相がズレたりベタ塗りに潰れたりする。AgXは白に向かって滑らかに脱色していくので、**強い光源・発光マテリアル・強いハイライトが自然に見える**。

つまり「眠く見える」のは不具合ではなく、**フィルムに近い挙動を再現した結果**。その代わり、素の状態はフラットで低コントラストになる。

## ルック（Look）

ビュー変換の後に **S字カーブを掛ける後段処理**。シャドウを締め、中間調の彩度を戻して「パンチ」を出す。

- 「なし（None）」がデフォルト
- 「非常に低いコントラスト」〜「非常に高いコントラスト」の段階が並ぶ（項目名・数はバージョンによって異なる）
- **「中から高コントラスト」が実用上の定番の出発点**とされる

AgXのハイライト保護を維持したままメリハリだけ足せるのが利点。

## なぜそうなるか（まとめ）

- レンダー結果はリニアHDR。**そのままでは画面に出せない**
- ビュー変換が「どう圧縮するか」を決め、その方針の違いが AgX / Filmic / 標準 の差になる
- ルックはその上の「味付け」であり、**シーンのライティングやマテリアルの値は一切変わらない**
- したがって、明暗の問題はライティングと露出で、メリハリの問題はルックで直す、と切り分けられる
- 外部ソフトでカラーグレーディングする前提なら、ルックは「なし」のままEXRで出力する
